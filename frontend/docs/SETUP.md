# Инструкция для владельца проекта: бэкенд, Vercel и Telegram

Проект из двух частей: **бэкенд** (`backend/`, NestJS + PostgreSQL — база, вход в админку, фото, Telegram-бот, ежедневные задачи) и **сайт** (`frontend/`, Next.js на Vercel). Ключи никому не пересылай и не вставляй в код — только в `.env`/`.env.local` (на своём компьютере), в настройки сервера и в настройки Vercel.

Интерфейсы сервисов иногда меняются. Если пункт меню называется немного иначе, ищи по смыслу.

---

## 1. Бэкенд (база данных, вход в админку, хранение фото)

Бэкенду нужен постоянно работающий сервер с диском: фото лежат в папке `uploads/`, а бот и ежедневные задачи работают внутри процесса. Vercel для этого не подходит. Бэкенд запускается в Docker одной командой: база PostgreSQL 17, сам бэкенд и Caddy (выдаёт https-сертификат) — всё описано в `docker-compose.prod.yml`.

**1. Сервер.** VPS с Ubuntu 24.04, от 2 ГБ памяти и 20 ГБ диска. Сервер лучше взять в Казахстане (например, PS.kz, Hoster.kz): по закону РК персональные данные — имена и телефоны из заявок — хранятся на территории страны. Хостинг пришлёт IP-адрес и пароль `root`. Подключись (`ssh root@<IP>`) и поставь Docker:

```bash
curl -fsSL https://get.docker.com | sh
```

Если у хостинга есть файрвол, открой порты 22, 80 и 443.

**2. Домен.** В панели регистратора домена добавь A-запись `api` → IP сервера. Адрес бэкенда будет `https://api.<домен>`. Подожди, пока `ping api.<домен>` начнёт показывать этот IP (обычно минуты, иногда до суток).

**3. Почта для входа в админку.** Нужен SMTP: бесплатный тариф [Resend](https://resend.com) или [Brevo](https://www.brevo.com) подойдёт. Строка вида `smtps://логин:пароль@smtp.сервис:465` → `SMTP_URL`, адрес отправителя → `MAIL_FROM`.

**4. Код и настройки.** На сервере:

```bash
git clone https://github.com/<аккаунт>/demalis.git   # приватный репозиторий: GitHub попросит логин и токен
cd demalis
cp backend/.env.example backend/.env
nano backend/.env
```

Что вписать в `backend/.env` (случайные строки — `openssl rand -hex 32`, выполни команду несколько раз):

- `POSTGRES_PASSWORD` — пароль базы (`openssl rand -hex 24`), и он же в `DATABASE_URL=postgresql://demalis:<пароль>@postgres:5432/demalis`;
- `JWT_SECRET`, `RATE_LIMIT_SECRET`, `INTERNAL_API_SECRET` — три разные случайные строки; `INTERNAL_API_SECRET` впиши и на Vercel (раздел 2);
- `SITE_URL` — адрес сайта, `PUBLIC_API_URL` — `https://api.<домен>`, `ADMIN_EMAILS` — email админов через запятую;
- `SMTP_URL`, `MAIL_FROM` — из п. 3;
- Telegram и `CRON_SECRET` — по разделам 2а–2б (можно позже).

**5. Запуск:**

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Первая сборка занимает несколько минут. Таблицы в базе создаются сами при старте. Проверка: `https://api.<домен>/health` в браузере отвечает `{"ok":true}`. Если нет — смотри логи: `docker compose -f docker-compose.prod.yml logs backend caddy`.

**6. Telegram-бот** (когда заполнены ключи из разделов 2а–2б):

```bash
docker compose -f docker-compose.prod.yml exec backend node --no-warnings scripts/set-webhook.ts
```

**Обновление** после изменений в коде:

```bash
cd demalis
git pull
docker compose -f docker-compose.prod.yml up -d --build
```

После правки `backend/.env` — та же команда `up -d` (без `git pull`).

**Резервные копии** базы и фото (храни копии не только на этом сервере):

```bash
docker compose -f docker-compose.prod.yml exec -T postgres pg_dump -U demalis demalis | gzip > db-$(date +%F).sql.gz
docker compose -f docker-compose.prod.yml cp backend:/app/uploads ./uploads-$(date +%F)
```

> ⚠️ **`JWT_SECRET` даёт вход в админку.** Никому не показывай, не добавляй префикс `NEXT_PUBLIC_`.
>
> Кнопка «Войти без письма» работает только при локальной разработке (`npm run dev` и бэкенд на этом компьютере). На сервере вход — только по ссылке из письма.

Тестовые объекты `[ТЕСТ]` (`npm run seed` в `backend/`) заливаются только локально — на сервер они не попадают.

## 2. Vercel (хостинг сайта)

1. Зайди на https://vercel.com → **Sign Up** → **Continue with GitHub**. Тариф — **Hobby** (бесплатный).
2. **Add New… → Project** → найди репозиторий `demalis` → **Import**. Если репозитория нет в списке, нажми **Adjust GitHub App Permissions** и дай доступ к нему.
3. **Framework Preset** определится сам (Next.js). **Root Directory** — `frontend`.
4. Открой **Environment Variables** и добавь переменные из `.env.example`. Нужны `NEXT_PUBLIC_SITE_NAME`, `NEXT_PUBLIC_SITE_URL`, `API_URL` и `NEXT_PUBLIC_API_URL` (https-адрес бэкенда), `INTERNAL_API_SECRET` (как на бэкенде) и `ADMIN_EMAILS` — без работающего бэкенда сборка не пройдёт.
5. **Deploy**. Через 1–2 минуты появится адрес вида `https://demalis-xxx.vercel.app`. Он должен открывать `/ru`.
6. **Settings → Functions → Function Region** → выбери регион поближе к серверу бэкенда.

Дальше каждый `git push` в ветку `main` сам обновляет сайт.

> ⚠️ **Бесплатный тариф Vercel — только для некоммерческих проектов.** Для разработки и проверки идеи этого хватает. Перед Этапом 8 (монетизация) проверь актуальные условия и при необходимости перейди на платный тариф или другой хостинг.

## 2а. Telegram: уведомления о заявках (Этап 4)

О каждой новой заявке сайт пишет в Telegram админу. Нужны бот и номер твоего чата.

1. В Telegram открой [@BotFather](https://t.me/BotFather) → `/newbot` → придумай имя и логин бота (должен кончаться на `bot`).
2. BotFather пришлёт токен вида `123456789:AA...` — это `TELEGRAM_BOT_TOKEN`. Никому его не показывай.
3. Найди своего бота по логину и нажми **Start** (бот не может писать тому, кто ему ни разу не писал).
4. Открой в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` (вместо `<ТОКЕН>` — токен из п. 2). В ответе найди `"chat":{"id":123456789` — это число и есть `ADMIN_TELEGRAM_CHAT_ID`.
   - Хочешь получать заявки в группу: добавь бота в группу, напиши там любое сообщение и снова открой ссылку — id группы начинается с минуса (`-100...`).
5. Впиши оба значения в `backend/.env` (и в настройки сервера бэкенда), затем перезапусти бэкенд.
6. Заполни и `SITE_URL` (адрес сайта) — тогда в сообщении будет ссылка на список заявок.

Если переменные не заданы, заявки всё равно сохраняются и видны в админке (`/admin/leads`), просто без сообщения в Telegram.

## 2б. Telegram-бот для владельцев (Этап 5)

Бот тот же, что в разделе 2а. Владельцы отмечают в нём свободные даты, получают заявки и напоминания.

**1. Секреты.** Придумай две длинные случайные строки (буквы и цифры, 30+ символов) и впиши в `backend/.env` (и на сервер бэкенда):

- `TELEGRAM_WEBHOOK_SECRET` — Telegram будет присылать её с каждым сообщением, чужие запросы бэкенд отклонит;
- `CRON_SECRET` — для ручного запуска ежедневных задач.

После этого перезапусти бэкенд.

**2. Подключить бота к бэкенду** (один раз, после деплоя и каждый раз при смене адреса бэкенда). Проще всего — открыть в браузере ссылку, подставив свои значения:

```
https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook?url=<PUBLIC_API_URL>/telegram/webhook&secret_token=<TELEGRAM_WEBHOOK_SECRET>
```

Ответ `"ok":true` — готово. Или из терминала: `cd backend && npm run bot:webhook` (берёт значения из `backend/.env`, адрес бэкенда должен быть `https://`).

**3. Привязать владельца.** Админка → «Владельцы» → «Добавить владельца» → «Создать код привязки». Отправь владельцу ссылку `t.me/…?start=КОД` (или код: он пишет боту `/start КОД`). Владелец выбирает язык — и бот показывает меню. Код одноразовый. Объекты владельцу назначаются в карточке объекта (поле «Владелец»).

**4. Ежедневный запуск** в 12:00 по Алматы (07:00 UTC) делает сам бэкенд (`src/cron/cron.service.ts`): по четвергам — напоминание «Обновите занятость на выходные»; 1-го числа — отчёт владельцам за прошлый месяц (Этап 9, если запуск сорвался — досылается 2-го и 3-го); каждый день — истёкший Pro возвращается на Free, а владельцу за 5 дней до конца Pro уходит напоминание (Этап 8). Проверить вручную: `curl -X POST <PUBLIC_API_URL>/cron/daily -H "Authorization: Bearer <CRON_SECRET>"`.

## 2в. Праздники: опрос владельцев про Новый год (Этап 13)

Админка → **«Праздники»**. По умолчанию — ночь 31.12 (дату можно поменять, например, на Наурыз).

1. Нажми **«Разослать опрос в боте»**. Каждый владелец с ботом получит по сообщению на каждый опубликованный объект: «Новый год: ночь 31.12 → 01.01 — есть свободные места?» с кнопками 🟢 / 🟡 / 🔴. После 🟢 или 🟡 бот спросит цену за ночь, её пишут числом (можно «Пропустить»).
2. Ответы сразу появляются в таблице на этой странице и на сайте. Владельцам без бота можно позвонить и отметить статус и цену в таблице самому.
3. Подборка **«Новый год за городом»** (`/ru/collections/novyj-god`) первой стоит на главной. На ночь 31.12 она показывает статусы и цены, свободные идут первыми. После 31.12 это обычная подборка; сними её с публикации или поменяй дату в «Подборках» (поле «Ночь»).

Продвижение на праздники стоит 30 000 ₸ в неделю, это отдельная строка в тарифах на `/owners` и в оферте. Оплату отмечай видом «Продвижение (праздники)», а дату окончания — как обычно в «Продвижение до» у объекта.

## 2г. Мониторинг: ошибки в Telegram и проверка доступности (Этап 13)

**Ошибки.** Бэкенд сам присылает в чат `ADMIN_TELEGRAM_CHAT_ID` (раздел 2а) сообщение «⚠️ Демалыс: ошибка», когда:

- запрос к API упал с ошибкой 5xx;
- не сработала отправка заявки владельцу;
- сломался бот или ежедневные задачи;
- часть сообщений владельцам не дошла.

Ошибки на страницах сайта (Vercel) сайт пересылает бэкенду, если у сайта заданы `API_URL` и `INTERNAL_API_SECRET`. Одинаковая ошибка приходит не чаще раза в 10 минут. Ничего дополнительно настраивать не нужно.

**Доступность — UptimeRobot (бесплатно, проверка раз в 5 минут).** Если упал сам сервер, бэкенд ничего прислать не сможет. Поэтому нужен внешний сторож:

1. Зарегистрируйся на [uptimerobot.com](https://uptimerobot.com) (бесплатный тариф).
2. **Add New Monitor** → тип **HTTP(s)** → адрес `https://api.<домен>/health` (то же, что `PUBLIC_API_URL` + `/health`; ответ `{"ok":true}` значит, что живы бэкенд и база), интервал 5 минут.
3. Второй монитор — сам сайт: `https://<домен>/ru`.
4. **My Settings → Alert Contacts → Add → Telegram**: открой ссылку на бота UptimeRobot и нажми Start. Включи этот контакт у обоих мониторов.
5. Проверка: в UptimeRobot у монитора нажми **Test notification** — в Telegram придёт сообщение.

**Резервные копии.** Сервис `backup` в `docker-compose.prod.yml` каждый день в 03:00 по Алматы сохраняет базу и фото в папку `backups/` на сервере. Если копия не получилась, придёт сообщение в тот же Telegram-чат. Как проверить, скачать к себе и восстановить — [deploy/backup/README.md](../../deploy/backup/README.md). Копия лежит на том же диске, что и сайт, поэтому раз в неделю скачивай её к себе.

## 2д. Даты, цены по дням и домики (Этап 14)

- **Выходные = обе ночи (пт и сб).** «Свободно на эти выходные» — только если свободны обе. В поиске есть «Будни» (ближайшие пн → ср), свои даты (заезд и выезд, до 14 ночей) и кнопки ближайших праздников.
- **Праздники** — список в `frontend/src/config/holidays.ts` (выходные дни подряд, с переносами). Переносы правительство объявляет каждый год: проверьте постановление и поправьте даты там же. Ночи накануне этих дней — праздничные, для них действует «цена в праздники».
- **Цены по дням** — в карточке объекта: будни (вс–чт), пт и сб, праздники. Все необязательные: сайт по ним считает «2 ночи ≈ X ₸». Пустая «Цена от» заполнится самой низкой из них. Колонки `price_weekday`, `price_weekend`, `price_holiday` есть и в CSV.
- **Домики.** Админка → объект → «Домики и номера». У каждого домика свои места и цены. Когда домики есть:
  - занятость отмечается по каждому: в сетке занятости выбери домик вверху, в боте владелец сначала выбирает домик или «Все домики сразу»;
  - статус объекта сайт считает сам: все свободны — «Свободно», часть — «Мало мест», все заняты — «Занято»;
  - «Гостей максимум» = сумма мест, а на даты гостям больше, чем мест в свободных домиках, объект показывается как «Занято»;
  - первый добавленный домик получает текущие отметки объекта, поэтому «Свободно» не пропадёт.

## 3. Локальный запуск на своём компьютере

См. `README.md` в корне репозитория: `docker compose up -d`, затем бэкенд (`backend/`) и сайт (`frontend/`). Сайт откроется на http://localhost:3000.
