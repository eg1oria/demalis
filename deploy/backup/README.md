# Резервные копии Демалыс

Каждый день в **03:00 по Алматы** сервер сам сохраняет копию базы (объекты,
заявки, владельцы, подборки, оплаты — всё) и всех фото. Этим занимается сервис
`backup` из `docker-compose.prod.yml`; он запускается вместе с остальными:

```bash
docker compose -f docker-compose.prod.yml up -d --build
```

Если копия не получилась, бот пришлёт админу в Telegram сообщение
«Демалыс: резервная копия не создана: …» с причиной (нужны
`TELEGRAM_BOT_TOKEN` и `ADMIN_TELEGRAM_CHAT_ID` в `backend/.env`). Когда всё
в порядке, сообщений нет.

Все команды ниже выполняются на сервере, в папке с репозиторием
(например, `cd ~/demalis`).

## Где лежат копии

В папке `backups/` рядом с `docker-compose.prod.yml`:

- `backups/db/demalis-2026-10-19.dump` — копия базы за этот день. Хранятся
  последние 14 дней, более старые удаляются сами.
- `backups/uploads/` — все фото. Новые фото докладываются каждую ночь,
  старые не удаляются никогда (даже если фото убрали с сайта).

Это обычная папка на диске сервера, а не volume Docker, поэтому
`docker compose down -v` её не сотрёт. В git она не попадает.

Сколько места занимает: `du -sh backups`

## Важно: скачивайте копии к себе

Копия лежит **на том же диске**, что и сам сайт. Она спасёт, если случайно
удалили данные или что-то сломалось при обновлении, но **не спасёт**, если
сломается или будет удалён сам сервер. Поэтому **раз в неделю скачивайте
папку к себе** на компьютер (а лучше ещё и в облако — Google Диск и т. п.).

С вашего компьютера (подставьте своего пользователя, адрес сервера и путь):

```bash
scp -r user@server:~/demalis/backups ./
```

## Проверить, что копии делаются

Сделать копию прямо сейчас (не дожидаясь ночи):

```bash
docker compose -f docker-compose.prod.yml run --rm -e BACKUP_NOW=1 backup
```

В конце должна быть строка `готово: db/demalis-….dump (…), фото: …`. Если
написано `ОШИБКА` — копия не создана, причина в той же строке.

Посмотреть, что сервис писал в последние дни:

```bash
docker compose -f docker-compose.prod.yml logs --tail 50 backup
```

## Восстановить базу

Это **заменит** текущие данные на сайте данными из копии: всё, что появилось
после этого дня, пропадёт. Перед восстановлением сделайте свежую копию
(команда выше) — на случай, если понадобится вернуть как было.

1. Остановить бэкенд, чтобы сайт не писал в базу во время восстановления:

   ```bash
   docker compose -f docker-compose.prod.yml stop backend
   ```

2. Восстановить базу из нужного дня (подставьте дату):

   ```bash
   docker compose -f docker-compose.prod.yml exec -T postgres pg_restore --clean --if-exists -U demalis -d demalis < backups/db/demalis-2026-10-19.dump
   ```

3. Запустить бэкенд обратно:

   ```bash
   docker compose -f docker-compose.prod.yml start backend
   ```

## Восстановить фото

Скопировать фото из копии обратно (уже существующие файлы не трогаются,
недостающие докладываются):

```bash
docker compose -f docker-compose.prod.yml run --rm --no-deps -u root -v "$PWD/backups/uploads:/restore:ro" backend sh -c 'cp -an /restore/. /app/uploads/ && chown -R node:node /app/uploads'
```

## Перенос на новый сервер

1. Установить всё по `frontend/docs/SETUP.md`, но перед первым запуском
   положить скачанную папку `backups/` в папку с репозиторием.
2. Запустить только базу: `docker compose -f docker-compose.prod.yml up -d postgres`
3. Восстановить базу и фото, как описано выше (шаг «Остановить бэкенд»
   пропустить).
4. Запустить всё: `docker compose -f docker-compose.prod.yml up -d --build`
